# 클러스터 배포

클러스터 배포는 프로덕션에서 대규모 작업을 실행하기 위해 여러 시스템에 DolphinScheduler를 배포하는 것입니다.

DolphinScheduler 기능을 처음 접하고 싶다면 [Standalone 배포](standalone.md)를 따라 설치하는 것이 좋습니다.보다 완벽한 기능을 경험하고 대규모 작업을 예약하려면 [pseudo-cluster 배포](pseudo-cluster.md)에 따라 설치하는 것이 좋습니다.DolphinScheduler를 프로덕션 환경에 배포하려면 [클러스터 배포](cluster.md) 또는 [Kubernetes 배포](kubernetes.md)를 따르는 것이 좋습니다.

## 배포 단계

클러스터 배포는 [의사 클러스터 배포](pseudo-cluster.md)와 동일한 스크립트 및 구성 파일을 사용하므로 준비 및 배포 단계는 의사 클러스터 배포와 동일합니다.차이점은 의사 클러스터 배포는 하나의 시스템에 대한 반면 클러스터 배포(클러스터)는 여러 시스템에 대한 것입니다.그리고 "구성 수정" 단계는 의사 클러스터 배포와 클러스터 배포 간에 상당히 다릅니다.

### 전제 조건 및 DolphinScheduler 시작 환경 준비

각 클러스터의 각 서버에 설치 패키지를 배포하고 각 머신에서 [의사-클러스터 배포](pseudo-cluster.md)의 모든 단계를 수행합니다.

> **_주의사항:_** 각 시스템의 구성 파일이 일관성이 있는지 확인하세요. 그렇지 않으면 클러스터가 제대로 작동하지 않습니다.
> **_주의 사항:_** 각 서비스는 상태가 없고 서로 독립적이므로 각 시스템에 여러 서비스를 배포할 수 있지만 포트 충돌에 주의해야 합니다.
> **_NOTICE:_** DS는 기본적으로 /tmp/dolphinscheduler 디렉토리를 리소스 센터로 사용합니다.리소스 센터의 디렉터리를 변경해야 하는 경우 conf/common.properties 파일에서 리소스 항목을 변경하세요.

### 구성 수정

이 단계는 [의사 클러스터 배포](pseudo-cluster.md)와 상당히 다릅니다. `scp` 또는 다른 방법을 사용하여 구성 파일을 각 시스템에 배포한 다음 구성 파일을 수정하세요.
