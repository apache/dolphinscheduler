### DolphinScheduler Alert SPI 메인 디자인

#### DolphinScheduler SPI 설계

DolphinScheduler는 마이크로커널 + 플러그인 아키텍처 변경을 겪고 있습니다.작업, 리소스 저장, 등록 센터 등과 같은 모든 핵심 기능은 확장 지점으로 설계됩니다.우리는 SPI를 사용하여 DolphinScheduler의 유연성과 친근감(확장 섹스)을 향상시키기를 희망합니다.

알람 관련 코드는 `dolphinscheduler-alert-api` 모듈을 참고하세요.이 모듈은 알람 플러그인의 확장 인터페이스와 일부 기본 코드를 정의합니다.관련 기능의 플러그인화를 실현해야 할 경우 먼저 이 블록의 코드를 읽는 것이 좋습니다.물론 문서를 읽어보는 것이 좋습니다.이렇게 하면 시간이 많이 단축되지만 문서가 어느 정도 지연되는 현상이 있습니다.문서가 누락된 경우, 소스코드를 기준으로 삼는 것이 좋습니다. (관심 있으신 분은 관련 문서 제출도 환영합니다.)또한 확장 인터페이스에 대한 변경은 거의 하지 않을 예정이며(신규 추가 제외), 큰 구조 조정이 없는 한 호환되지 않는 업그레이드 버전도 있으므로 기존 문서는 대체적으로 만족할 수 있습니다.

우리는 확장이 필요할 때 기본 JAVA-SPI를 사용합니다. 실제로 `org.apache.dolphinscheduler.alert.api.AlertChannelFactory` 인터페이스의 확장에만 주의하면 됩니다. 플러그인 로딩과 같은 기본 로직과 기타 커널이 구현되어 있으므로 개발이 더욱 집중되고 단순해집니다.

또한 `AlertChannelFactory`는 `PrioritySPI`에서 확장됩니다. 즉, 플러그인 우선순위를 설정할 수 있으며, 이름이 같은 두 플러그인이 있는 경우 `getIdentify` 메소드를 재정의하여 우선순위를 사용자 정의할 수 있습니다.우선순위가 높은 플러그인이 로드되지만 이름과 우선순위가 같은 두 개의 플러그인이 있는 경우 플러그인을 로드할 때 서버에서 'IllegalArgumentException'이 발생합니다.

그런데 우리는 JSON을 기반으로 하는 프런트 엔드 UI 구성 요소 생성을 지원하는 우수한 프런트 엔드 구성 요소 form-create를 채택했습니다.플러그인 개발에 프런트엔드가 포함된 경우 JSON을 사용하여 관련 프런트엔드 UI 구성 요소인 org.apache.dolphinscheduler를 생성합니다.플러그인의 매개변수는 spi.params에 캡슐화되어 모든 관련 매개변수를 해당 JSON으로 변환합니다. 즉, Java 코드를 통해 프런트엔드 구성 요소 그리기를 완료할 수 있습니다(여기서는 주로 양식이며 프런트엔드와 백엔드 간에 교환되는 데이터만 고려합니다).

이 문서에서는 주로 Alert의 설계 및 개발에 중점을 둡니다.

#### 메인 모듈

내부 디자인에는 관심이 없지만 단순히 자신만의 알람 플러그인을 개발하는 방법을 알고 싶다면 이 콘텐츠를 건너뛰어도 됩니다.

* 돌고래 스케줄러-경고-API

이 모듈은 ALERT SPI의 핵심 모듈입니다.이 모듈은 알람 플러그인 확장의 인터페이스와 일부 기본 코드를 정의합니다.확장 플러그인은 `org.apache.dolphinscheduler.alert.api.AlertChannelFactory` 모듈에서 정의한 인터페이스를 구현해야 합니다.

* 돌고래 스케줄러-경고-플러그인

이 모듈은 현재 당사에서 제공하는 플러그인으로, 현재 Email, DingTalk, Script 등 수십 개의 플러그인을 지원하고 있습니다.

#### SPI 메인 클래스 정보를 경고합니다.

AlertChannelFactory
알람 플러그인 공장 인터페이스.모든 알람 플러그인은 이 인터페이스를 구현해야 합니다.이 인터페이스는 알람 플러그인의 이름과 필수 매개변수를 정의하는 데 사용됩니다.create 메소드는 특정 알람 플러그인 인스턴스를 생성하는 데 사용됩니다.

경고 채널
경고 플러그인의 인터페이스입니다.경고 플러그인은 이 인터페이스를 구현해야 합니다.이 인터페이스에는 메소드 프로세스가 하나만 있습니다.상위 경보 시스템은 이 메소드를 호출하고 이 메소드가 반환하는 AlertResult를 통해 경보의 반환 정보를 얻습니다.

경고데이터
ID, 제목, 내용, 로그를 포함한 알람 내용 정보입니다.경고 정보
알람 관련 정보는 상위 시스템에서 알람 플러그인의 인스턴스를 호출하면 이 클래스의 인스턴스가 process 메소드를 통해 특정 알람 플러그인으로 전달된다.여기에는 경고 콘텐츠 AlertData와 호출된 경고 플러그인 인스턴스의 프런트 엔드에서 채워진 매개변수 정보가 포함됩니다.

경고 결과
알람 플러그인은 알람 반환 정보를 보냅니다.

org.apache.dolphinscheduler.spi.params
이 패키지는 플러그인 매개변수 정의입니다.우리의 프런트엔드는 플러그인 정의에서 반환된 매개변수 목록 json을 기반으로 프런트엔드 UI를 동적으로 생성할 수 있는 from-create 프런트엔드 라이브러리(http://www.form-create.com)를 사용하므로 SPI 플러그인 개발을 수행할 때 프런트엔드에 신경 쓸 필요가 없습니다.

이 패키지에서는 현재 각각 텍스트 유형 매개변수, 라디오 매개변수 및 비밀번호 유형 매개변수를 정의하는 데 사용되는 RadioParam, TextParam 및 PasswordParam만 캡슐화합니다.

AbsPluginParams 이 클래스는 모든 매개변수의 기본 클래스이며 RadioParam 이러한 클래스는 모두 이 클래스를 상속합니다.각 DS 경고 플러그인은 AlertChannelFactory 구현 시 AbsPluginParams 목록을 반환합니다.

Alert_spi의 구체적인 디자인은 문제: [Alert Plugin Design](https://github.com/apache/dolphinscheduler/issues/3049)에서 확인할 수 있습니다.
