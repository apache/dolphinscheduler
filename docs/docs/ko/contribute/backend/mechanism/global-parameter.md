# 글로벌 매개변수 개발 문서

사용자가 OUT 방향으로 매개변수를 정의한 후 해당 매개변수는 작업의 localParam에 저장됩니다.

## 매개변수 사용법

DAG에서 생성할 현재 `taskInstance`의 직접 선행 노드 `preTasks`를 가져오고, `preTasks`의 `varPool`을 가져와 이 varPool(List)을 하나의 `varPool`로 병합하고, 병합 프로세스에서 동일한 매개변수 이름을 가진 매개변수가 발견되면 다음 논리에 따라 처리됩니다.

* 모든 값이 null인 경우 병합된 값은 null입니다.
* 하나의 값만 null이 아닌 경우 병합된 값은 null이 아닌 값입니다.
* 모든 값이 null이 아닌 경우 VarPool이 취한 taskInstance의 종료 시간 중 가장 빠른 값이 됩니다.

병합된 모든 속성의 방향은 병합 프로세스 중에 IN으로 업데이트됩니다.

병합 결과는 taskInstance.varPool에 저장됩니다.

작업자는 varPool을 받아 `Map<String,Property>` 형식으로 구문 분석합니다. 여기서 맵의 키는 매개변수 이름인 property.prop입니다.

프로세서가 매개변수를 처리할 때 varPool, localParam 및 globalParam 매개변수를 병합하며, 병합 프로세스 중에 이름이 중복된 매개변수가 있으면 다음 우선순위에 따라 교체됩니다. 즉, 높은 우선순위는 유지되고 낮은 우선순위는 교체됩니다.

* globalParam: 높음
* varPool: 중간
* localParam: 낮음

매개변수는 노드 콘텐츠가 실행되기 전에 ${매개변수 이름}과 비교하여 정규식을 사용하여 해당 값으로 대체됩니다.

## 매개변수 설정

현재 매개변수 가져오기에는 SQL 및 SHELL 노드만 지원됩니다.

localParam에서 OUT 방향의 매개변수를 가져오고, 다른 노드의 유형에 따라 다음과 같은 방법을 수행합니다.

### SQL 노드

매개변수에 의해 반환되는 구조는 List<Map<String,String>>입니다. 여기서 List의 요소는 데이터의 각 행이고 Map의 키는 열 이름이며 값은 열에 해당하는 값입니다.

* SQL 문이 한 행의 데이터를 반환하는 경우 사용자가 태스크 정의 시 정의한 OUT 매개변수 이름을 기준으로 OUT 매개변수 이름을 일치시키거나, 일치하지 않으면 폐기합니다.
* SQL 문이 여러 행의 데이터를 반환하는 경우 LIST 유형의 작업을 정의할 때 사용자가 정의한 OUT 매개변수 이름을 기반으로 열 이름이 일치됩니다.해당 열의 모든 행이 이 매개변수의 값으로 `List<String>`으로 변환됩니다.일치하는 항목이 없으면 삭제됩니다.

### SHELL 노드

프로세서 실행 결과는 `Map<String,String>`으로 반환됩니다.

사용자는 쉘 스크립트를 정의할 때 출력에 `${setValue(key=value)}`를 정의해야 합니다.

"="로 분할된 매개변수를 처리할 때 `${setValue()}`를 제거합니다. 0은 키이고 1은 값입니다.

마찬가지로 작업 정의 시 사용자가 정의한 OUT 매개변수 이름과 키를 일치시키고 value를 해당 매개변수의 값으로 사용합니다.

반환 매개변수 처리

* 획득한 프로세서의 결과는 문자열입니다.
* 프로세서가 비어 있는지 확인하고 비어 있으면 종료합니다.
* localParam이 비어 있는지 확인하고, 비어 있으면 종료합니다.
* OUT인 localParam의 매개변수를 가져와 비어 있으면 종료합니다.
* 어필 형식에 따라 문자열 형식을 지정합니다(SQL의 경우 `List<Map<String,String>>`, 셸의 경우 `Map<String,String>>`).

일치하는 값을 가진 매개변수를 varPool(원본 IN의 매개변수가 포함된 목록)에 할당합니다.

* varPool을 json으로 포맷하고 마스터에 전달합니다.
* OUT인 매개변수는 마스터가 varPool을 수신한 후 localParam에 기록됩니다.
