# 로깅 사양

## 서문

로그는 시스템 개발 및 운영 중 다양한 작업을 추적하고 기록하는 데 사용됩니다.표준화된 로그 인쇄는 사용자나 개발자가 시스템 작동 상태를 빠르게 이해하고 문제를 찾는 데 도움이 됩니다.

Apache DolphinScheduler는 Logback 로깅 프레임워크를 사용하여 DEBUG, WARN, INFO 및 ERROR의 네 가지 수준에 따라 로그를 인쇄하며 우선 순위는 DEBUG < INFO < WARN < ERROR입니다.

## 사양

### 로깅 수준 사양

다양한 수준의 로그는 비즈니스 프로세스에서 다양한 역할을 하며, 인쇄에 적합한 로그 수준을 사용하지 않으면 시스템 운영 및 유지 관리에 큰 어려움을 초래할 수 있습니다.

- DEBUG 레벨은 개발 및 테스트 과정에서 디버깅 정보를 출력하는 데 사용됩니다.개발자는 개발 및 테스트 단계에서 문제를 쉽게 찾고 분석할 수 있도록 이 수준을 사용하여 디버깅 중에 매개 변수 정보, 프로세스 세부 정보 및 결과 정보를 최대한 인쇄해야 합니다.또한 프로덕션 환경에서 로그를 인쇄하는 데 이 수준을 사용하는 것도 금지됩니다.
- INFO 레벨은 시스템 운영 중 정보를 기록하는 데 사용됩니다.이 수준을 사용하여 인쇄된 로그는 워크플로, 작업 등의 상태 변경과 같은 시스템 동작을 반영할 수 있어야 합니다.
- WARN 레벨은 운전 중 발생할 수 있는 문제에 대해 경고하는 데 사용됩니다.예를 들어 API 모듈 매개변수의 체크섬 등이 있습니다.
- ERROR 레벨은 시스템 프로세스에 영향을 미치는 예측할 수 없는 오류 및 예외를 기록하는 데 사용됩니다.예를 들어 워크플로 및 작업이 제대로 완료되지 못하게 하는 오류 및 예외가 있습니다.

### 로깅 콘텐츠 사양

로그 내용은 로그가 시스템 동작이나 상태를 완전히 복원할 수 있는지 여부를 결정합니다.

- DEBUG 수준 로그는 개발 프로세스 중 디버깅 정보를 기록하고 디버깅이 필요한 중요한 프로그램에 나타나며 자세한 사이트 정보, 매개 변수, 결과 등을 포함합니다.

- INFO 수준의 로그는 현재 프로그램 호출의 상태 정보나 동작 정보를 기록해야 하며, 시스템 동작 과정을 기술하는 역할을 한다.따라서 이 수준의 로그는 시스템 작동의 임계점에 나타나야 하며 로그 내용에는 임계점, 매개변수 및 결과에 대한 설명이 포함되어야 합니다.예를 들어 워크플로 인스턴스가 예약되면 각 주요 링크의 상태 변경이 인쇄됩니다.

- WARN 수준 로그는 시스템이나 기능의 정상적인 작동에 영향을 주지 않는 현재 프로그램 호출에서 발생하는 허용 가능한 오류에 대한 정보를 기록합니다. 그러나 이 수준 로그의 내용은 자세한 사이트 설명, 매개 변수 및 결과도 포함해야 합니다.예를 들어 API 모듈 인터페이스 매개변수 확인에 실패하면 확인 실패에 대한 설명과 매개변수가 기록됩니다.

- ERROR 수준 로그는 현재 프로그램 호출에서 발생하는 허용할 수 없는 오류에 대한 정보를 기록합니다. 이로 인해 시스템이나 기능이 정상적으로 작동하지 못할 수 있습니다.따라서 이 수준의 로그에는 오류 설명, 사이트 매개변수, 오류 결과 등을 자세히 기록해야 로그를 기반으로 문제와 원인을 빠르게 찾을 수 있습니다.또한 예외를 처리할 때 스택 정보를 인쇄하려면 다음 형식을 사용하십시오.  ```java
  logger.error("description of current error, parameter is {}", parameter, e);
````

### 로깅 형식 사양

마스터 모듈과 워커 모듈의 로그는 다음과 같은 형식으로 출력됩니다.```xml
[%level] %date{yyyy-MM-dd HH:mm:ss.SSS Z} %logger{96}:[%line] - [WorkflowInstance-%X{workflowInstanceId:-0}][TaskInstance-%X{taskInstanceId:-0}] - %msg%n
````

즉, 워크플로 인스턴스 ID와 태스크 인스턴스 ID는 MDC를 사용하여 인쇄된 로그에 삽입되므로 개발자는 이 두 모듈의 워크플로 인스턴스 및 태스크 인스턴스와 관련된 로그를 인쇄하기 전에 ID를 가져와 삽입해야 합니다.인쇄가 완료된 후에는 관련 ID를 제거해야 합니다.

## 로깅 구성

DolphinScheduler는 로깅을 위해 [LogBack](https://docs.spring.io/spring-boot/docs/2.1.8.RELEASE/reference/html/howto-logging.html)을 사용합니다.특정 패키지의 로깅 레벨을 변경하려면 해당 모듈의 `logback-spring.xml` 파일을 수정해야 합니다.
예를 들어, `standalone` 모듈의 `org.springframework.web` 패키지에 대해 `DEBUG` 로깅을 활성화하려면 `apache-dolphinscheduler-dev-SNAPSHOT-bin/standalone-server/conf/logback-spring.xml`에 다음 구성을 추가해야 합니다.```xml
<configuration scan="true" scanPeriod="120 seconds">

......

  <logger name="org.springframework.web" level="DEBUG">
    <appender-ref ref="STANDALONELOGFILE" />
    <appender-ref ref="TASKLOGFILE"/>
  </logger>

......

</configuration>
````

## 주의사항

- 로그 인쇄를 위한 표준 출력 사용을 비활성화합니다.표준 출력은 시스템 성능에 큰 영향을 미칠 수 있습니다.
- 예외 처리를 위해 printStackTrace() 사용을 금지합니다.이 메서드는 예외 스택 정보를 표준 오류 출력에 인쇄합니다.
- 로그의 분기 인쇄는 금지됩니다.로그의 내용은 해당 정보와 로그 형식으로 연결되어야 하며, 이를 별도의 줄로 인쇄하면 로그의 내용이 시간 및 기타 정보와 일치하지 않게 되고, 다수의 로그 환경에서 로그가 혼합되어 로그 검색이 더욱 어려워지게 됩니다.
- 로그 내용을 이어붙이는 데 "+" 연산자를 사용하는 것은 금지됩니다.메모리 사용 효율성을 높이기 위해 인쇄용 로그 형식 지정에 자리 표시자를 사용합니다.
- 로그 내용에 객체 인스턴스가 포함된 경우 의미 없는 해시코드가 인쇄되지 않도록 toString() 메서드를 재정의해야 합니다.
