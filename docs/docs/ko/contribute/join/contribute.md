# 기부에 참여하세요

우선, DolphinScheduler를 선택하고 사용해 주셔서 진심으로 감사드리며, DolphinScheduler 가족이 되신 것을 환영합니다!

우리는 궁극적으로 Committer 또는 PPMC가 될 커뮤니티에 다음과 같은 모든 형태의 참여를 권장합니다.
* 문제는 [문제](https://github.com/apache/dolphinscheduler/issues) 양식 피드백에서 github을 통해 발생합니다.
* 다른 사람들이 묻는 문제 질문에 답하십시오.
* 문서 개선에 도움을 주세요.
* 프로젝트에 테스트 케이스를 추가하도록 도와주세요.
* 코드에 주석을 추가합니다.
* 버그나 기능을 수정한 PR을 제출하세요.
* 응용 사례 실습, 일정 프로세스 분석 또는 일정 관련 기술 기사를 게시합니다.
* DolphinScheduler 홍보, 기술 컨퍼런스 또는 모임 참여, 공유 등에 도움을 주세요.

기여 팀에 오신 것을 환영하며 첫 번째 PR 제출부터 시작하여 오픈 소스에 참여하세요.
- 예를 들어 코드 주석을 추가하거나 "수정하기 쉬운" 태그 또는 매우 간단한 문제(철자 오류 등)를 찾는 등 먼저 첫 번째 간단한 PR을 통해 제출 프로세스를 숙지하세요.

참고: 기여는 PR에만 국한되지 않고 프로젝트 개발에 기여합니다.

DolphinScheduler에 참여하시면 오픈소스의 혜택을 누리실 수 있을 거라 확신합니다!

### 1. 문서 기여에 참여하세요.

[제출안내-문서공지](./document.md)를 참고하세요.

### 2. 코드 기여에 참여합니다.

[가이드 제출-문제 공지](./issue.md), [가이드 제출-Pull 요청 공지](./pull-request.md), [가이드 제출-커밋 메시지 공지](./commit-message.md)를 참고하세요.

### 3. 이슈를 선택하고 Pull Request를 제출하는 방법.

기능을 구현하거나 버그를 수정하려는 경우.다음을 참고하세요.

* 모든 버그 및 기능은 GitHub 이슈(https://github.com/apache/dolphinscheduler/issues)를 통해 권장 및 관리됩니다.
* 기능을 개발하려는 경우 먼저 해당 기능과 관련된 문제에 응답하여 현재 작업 중임을 나타냅니다.그리고 기능을 제출할 때 "마감일"을 설정하고 회신 댓글에 추가하세요.
* 핵심 기여자 중에서 디자인과 기능 구현에 대한 즉각적인 피드백을 줄 수 있는 멘토(또는 강사)를 찾는 것이 좋습니다.
* 작업을 시작하려면 새 브랜치를 생성해야 하며, 브랜치 이름을 확인하려면 [제출 가이드-Pull 요청 공지](./pull-request.md)를 참조하세요.예를 들어 기능을 완료하고 Issue 111을 제출하려면 지점 이름이 feature-111이어야 합니다.기능 명칭은 강사와 협의 후 결정될 수 있습니다.
* 작업이 완료되면 Dolphinscheduler에 Pull Request를 보내주세요. 《[Submit Guide-Submit Pull Request Process](./submit-code.md)》를 참고해주세요.

기능을 완료하거나 버그를 수정하기 위해 Pull Request를 제출하려면 `좋은 첫 번째 문제`, `수정하기 쉬운` 문제부터 시작하여 제출할 작은 기능을 완료하고, 한 번에 너무 많은 파일을 변경하지 말고, 너무 많은 파일을 변경하면 리뷰어에게 많은 부담을 줄 수 있으므로, 한 번에 모두가 아닌 여러 개의 Pull Request를 통해 제출하는 것이 좋습니다.
