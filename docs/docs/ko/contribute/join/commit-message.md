# 커밋 메시지 알림

### 서문

좋은 커밋 메시지는 다른 개발자(또는 향후 개발자)가 관련 변경 내용을 빠르게 이해하는 데 도움이 될 수 있으며 프로젝트 관리자가 커밋이 릴리스에 포함하기에 적합한지 여부를 결정하는 데도 도움이 될 수 있습니다.하지만 많은 오픈소스 프로젝트의 커밋 로그를 확인하면서 흥미로운 문제를 발견했습니다.일부 개발자는 코드 품질이 매우 좋지만 커밋 메시지 기록이 다소 혼란스럽습니다.다른 기여자나 학습자가 코드를 볼 때는 커밋 로그를 통해 직관적으로 이해할 수 없습니다.
Peter Hutterer가 말했듯이 제출 전후 변경의 목적은 다음과 같습니다. 코드 일부의 컨텍스트를 다시 설정하는 것은 낭비입니다.완전히 피할 수는 없으므로 최대한 줄이는 데 노력해야 합니다.커밋 메시지는 바로 이를 수행할 수 있으며 결과적으로 커밋 메시지는 개발자가 좋은 협력자인지 여부를 보여줍니다.따라서 DolphinScheduler는 다른 커뮤니티 및 공식 Apache 문서와 함께 프로토콜을 개발했습니다.

### 커밋 메시지 RIP

#### 1：내용을 명확하게 수정하세요

커밋 메시지에는 제출로 해결되는 문제(버그 수정, 기능 향상 등)가 무엇인지 명확하게 명시해야 합니다. 그래야 다른 개발자가 버전 반복 프로세스 중에 문제를 더 잘 추적하고 최적화를 명확히 할 수 있습니다.

#### 2：해당 Pull Request 또는 Issue를 연관시킵니다.

변경 사항이 큰 경우 커밋 메시지는 GitHub의 관련 이슈 또는 풀 요청과 가장 잘 연결되어야 합니다. 그래야 개발자가 코드를 검토할 때 관련 정보를 통해 코드 제출의 컨텍스트를 빠르게 이해할 수 있습니다.현재 커밋이 문제에 대한 것이라면 해당 문제는 바닥글 섹션에서 닫힐 수 있습니다.

#### 3: 통일된 형식

형식화된 CommitMessage는 빠른 탐색을 위해 더 많은 기록 정보를 제공하는 데 도움이 될 수 있으며 커밋에서 직접 변경 로그를 생성할 수도 있습니다.

커밋 메시지에는 머리글, 본문, 바닥글의 세 부분이 포함되어야 합니다.그 중 Header는 필수이며, Body와 Footer는 생략 가능합니다.

##### 헤더

헤더 부분에는 유형(필수), 범위(선택), 제목(필수)의 세 가지 필드를 포함하여 한 줄만 있습니다.

[DS-ISSUE 번호][유형] 제목

(1) Type은 커밋의 종류를 나타내는데 사용되며, 다음 7가지 유형만 허용된다.

- 특기：특징
- 수정: 버그 수정
- 문서：문서
- 스타일： 형식(코드 작업 변경에는 영향을 주지 않음)
- 리팩토링：리팩토링(버그를 수정하기 위한 새로운 기능이나 코드 변경이 아닙니다)
- 테스트 : 테스트 추가
- 집안일: 빌드 프로세스 또는 보조 도구의 변경

유형이 feat and fix인 경우 커밋이 변경 로그에 확실히 표시됩니다.다른 유형(문서, 잡일, 스타일, 리팩터링, 테스트)은 권장되지 않습니다.

(2) 범위

범위는 서버, 원격 등 커밋 영향의 범위를 나타내는 데 사용됩니다. 적합한 범위가 없으면 \*를 사용할 수 있습니다.

(3) 주제

제목은 커밋 목적에 대한 간단한 설명으로, 50자 이내입니다.

##### 본체

본문 부분은 이 커밋에 대한 자세한 설명으로 여러 줄로 나눌 수 있으며 줄 바꿈은 모양에 영향을 미치는 자동 줄 바꿈을 방지하기 위해 72자로 줄바꿈됩니다.

본문 섹션에서 다음 사항에 유의하세요.

- 동사-목적어 구조를 사용하고, 현재 시제 사용에 유의하세요.예를 들어 변경 또는 변경 대신 변경을 사용합니다.

- 첫 글자를 대문자로 쓰지 마세요.

- 문장 끝에는 '.'(마침표)이 필요하지 않습니다.

##### 바닥글

바닥글은 두 가지 상황에서만 작동합니다.

(1) 호환되지 않는 변경 사항

현재 코드가 이전 버전과 호환되지 않는 경우 바닥글 부분은 MARKING CHANGE로 시작하고 변경 내용에 대한 설명, 변경 이유, 마이그레이션 방법이 이어집니다.

(2) 이슈 종료

현재 커밋이 특정 문제에 대한 것이라면 바닥글 섹션에서 문제를 닫거나 여러 문제를 한 번에 닫을 수 있습니다.

##### 예를 들어```
[DS-001][docs-en] add commit message

- commit message RIP
- build some conventions
- help the commit messages become clean and tidy
- help developers and release managers better track issues
  and clarify the optimization in the version iteration

This closes #001
````
